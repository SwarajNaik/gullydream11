# GullyDream11 — Dream11 Clone (Web-Based Fantasy Cricket Platform)

## Complete Project Specification for Claude Code

---

## 1. PROJECT OVERVIEW

**GullyDream11** is a web-based fantasy cricket platform that replicates the Dream11 experience. Players create virtual cricket teams from real-world players, join contests/tournaments created by admins, and earn points based on real-life player performance. The platform is designed for private/community use — payments happen offline (physically), and the system only tracks winnings, entry fees owed, and balances.

### Core Principles
- **Exact Dream11 UI clone** — Dark theme, red/black/white color palette, card-based layout, bottom navigation
- **Community/private use** — No real payment gateway; offline settlement with on-platform record keeping
- **Admin-managed tournaments** — Admins create matches, contests, set entry fees, prize pools, and manage scoring
- **Free-tier infrastructure** — No paid auth services; self-hosted JWT-based auth
- **Production-grade architecture** — Monorepo, typed end-to-end, modular services, scalable design

enum TransactionType {

  WINNING             // Prize money credited
  REFUND              // Contest cancelled refund
  ADMIN_CREDIT        // Admin manually credits
  ADMIN_DEBIT         // Admin manually debits
  SETTLEMENT_PAID     // Offline payment made (reduces pendingDues)
  SETTLEMENT_RECEIVED // Offline payment received (reduces pendingReceive)

  COMPLETED

### 8.2 Fantasy Points Calculation
```typescript
function calculateFantasyPoints(score: PlayerScore, role: PlayerRole): number {
  let points = 0;
  
  // Starting XI bonus
  if (score.isStartingXI) points += SCORING.STARTING_XI;
  
  // Batting points
  points += score.runs * SCORING.RUN;
  points += score.fours * SCORING.BOUNDARY_FOUR;
  points += score.sixes * SCORING.BOUNDARY_SIX;
  if (score.runs >= 100) points += SCORING.CENTURY;
  else if (score.runs >= 50) points += SCORING.HALF_CENTURY;
  if (score.runs === 0 && score.balls > 0 && ['BAT', 'WK', 'AR'].includes(role)) {
    points += SCORING.DUCK;
  }
  
  // Strike rate bonus/penalty (min 10 balls)
  if (score.balls >= 10) {
    const sr = (score.runs / score.balls) * 100;
    if (sr > 170) points += SCORING.SR_ABOVE_170;
    else if (sr >= 150) points += SCORING.SR_150_TO_170;
    // ... etc
  }
  
  // Bowling points
  points += score.wickets * SCORING.WICKET;
  if (score.wickets >= 5) points += SCORING.WICKET_BONUS_5;
  else if (score.wickets >= 4) points += SCORING.WICKET_BONUS_4;
  else if (score.wickets >= 3) points += SCORING.WICKET_BONUS_3;
  points += score.maidens * SCORING.MAIDEN;
  
  // Economy bonus/penalty (min 2 overs)
  if (score.overs >= 2) {
    const eco = score.runsConceded / score.overs;
    // ... economy brackets
  }
  
  // Fielding
  points += score.catches * SCORING.CATCH;
  if (score.catches >= 3) points += SCORING.CATCH_BONUS_3;
  points += score.stumpings * SCORING.STUMPING;
  points += score.runOuts * SCORING.RUN_OUT_DIRECT;
  
  return points;
}
```

## 9. MIDDLEWARE & AUTH

### Role-Based Access Control
```typescript
// middleware.ts
export function middleware(req: NextRequest) {
  const session = await getToken({ req });
  
  // Protect /admin routes — only ADMIN role
  if (req.nextUrl.pathname.startsWith('/admin')) {
    if (!session || session.role !== 'ADMIN') {
      return NextResponse.redirect(new URL('/home', req.url));
    }
  }
  
  // Protect /api/admin routes
  if (req.nextUrl.pathname.startsWith('/api/admin')) {
    if (!session || session.role !== 'ADMIN') {
      return NextResponse.json({ error: 'Unauthorized' }, { status: 403 });
    }
  }
  
  // Protect all (main) routes — require auth
  if (req.nextUrl.pathname.startsWith('/(main)')) {
    if (!session) {
      return NextResponse.redirect(new URL('/login', req.url));
    }
  }
}
```

## 14. KEY TECHNICAL DECISIONS

1. **No separate backend service** — Next.js API routes handle everything (simpler deployment, fewer moving parts for a community project)
2. **Prisma over raw SQL** — Type safety, auto-generated client, easy migrations
3. **JWT auth over sessions** — Stateless, no session store needed, works with SSR
4. **Redis for caching** — Leaderboard caching, match status, contest fill counts
5. **BullMQ for async jobs** — Score processing, prize distribution, leaderboard recalculation
6. **Zod schemas shared** — Same validation on client and server, single source of truth
7. **Server Components by default** — Better performance, less client JS
8. **Optimistic UI updates** — Contest join, team save feel instant
9. **No payment gateway** — Wallet is a ledger only; settlements tracked but happen offline
10. **Mobile-first responsive** — Design for 375px width first, scale up

## 15. IMPORTANT NOTES FOR CLAUDE CODE

- **Start with `docker-compose up -d`** to bring up Postgres and Redis before anything

- **Admin can do everything** — create tournaments, matches, contests, enter scores, distribute prizes, manage users, manage settlements
